# VLC 3.6.5 Android AAR 构建脚手架

用于把 [vlc_3.6.5_new](https://github.com/xingkongyu/vlc_3.6.5_new)（VLC 3.6.5 core 定制版）
编译成 Android AAR 的完整脚手架。基于上游 `vlc-android` 的 `libvlc-3.6.5` tag +
`libvlcjni` 的 `965e8648`，并叠加了本项目需要的构建与 JNI 定制。

产物：`libvlc.so` + `libvlcjni.so` + `libc++_shared.so`，打包为 `libvlc-release-<时间戳>.aar`。
已验证的稳定版 AAR 存放在 core 仓库的 [`aar/`](https://github.com/xingkongyu/vlc_3.6.5_new/tree/main/aar) 目录。

---

## 一、目录结构

```
vlc-aar-3.6.5/
├── buildsystem/
│   └── compile.sh                # 上游构建入口（-a arm -l -t -b release）
├── libvlcjni/
│   ├── buildsystem/
│   │   └── compile-libvlc.sh     # 真正调 configure/make 的脚本（本仓库有定制）
│   ├── libvlc/
│   │   ├── jni/                  # JNI 层（本仓库有定制）
│   │   ├── src/org/videolan/libvlc/   # Java 层（本仓库有定制）
│   │   └── assets/               # 字体与 fontconfig 缓存
│   ├── build.gradle / settings.gradle
│   └── vlc -> ../../vlc_core-3.6.5   # 构建时建立，指向 core 源码（不入库）
├── gradle/wrapper/               # Gradle wrapper 配置（指向腾讯镜像）
├── build.gradle / settings.gradle
└── build_libvlc_3.6.5_aar.sh     # 一键构建脚本
```

## 二、相对上游的定制

### 2.1 构建脚本

| 文件 | 改动 |
|---|---|
| `buildsystem/compile.sh` | ① 本地预编译 contrib 包直通：存在 `contrib/contrib-android-<triplet>/vlc-contrib-<triplet>-latest.tar.zst` 就启用 `--with-prebuilt-contribs`，跳过 SHA 计算与 check-url；② `VLC_CONTRIB_SHA` 支持环境变量覆盖；③ 下载地址改 `.tar.zst` |
| `libvlcjni/buildsystem/compile-libvlc.sh` | `--disable-nfs`（contrib 的 libnfs 16.x 与 3.6.5 的 5.x API 不兼容）；`--enable-live555`（实测可编，旧记录"必须 disable"已作废）；`--enable-smb2` |

### 2.2 JNI 层

| 文件 | 改动 |
|---|---|
| `libvlc/jni/libvlcjni.c` | `setup_fontconfig()`：生成最小 `fonts.conf`（`/system/fonts`、`/product/fonts`、`/vendor/fonts` + 可写 cachedir），`setenv("FONTCONFIG_FILE")` |
| `libvlc/jni/libvlcjni-mediaplayer.c` | 文本字幕桥 `nativeSetSubtitleTextListener`；位图字幕桥 `nativeSetSubtitleBitmapListener`（含 RGBA 回传）；`nativeSetSubtitleScale` / `nativeSetSubtitleColor` |

### 2.3 Java 层

| 文件 | 改动 |
|---|---|
| `LibVLC.java` | `prepareFontDir()` / `prepareFontCache()`：把 AAR 内 `assets/fonts`、`assets/fontconfig` 拷到应用私有目录；构造时先准备再 `nativeNew` |
| `MediaPlayer.java` | `SubtitleTextListener`、`SubtitleBitmapListener` 接口；`setSubtitleScale/Color`、`setSubtitleTextListener`、`setSubtitleBitmapListener` |

### 2.4 资源

- `libvlc/assets/fontconfig/*.cache-7`（663 KB）：设备上预生成的 fontconfig 缓存
- `libvlc/assets/fonts/NotoSansSC-subset.otf`（5.3 MB）：中文子集字体

## 三、构建

### 3.1 环境要求（Ubuntu 24.04 实测）

```bash
sudo apt-get install -y build-essential autoconf automake libtool libtool-bin \
    pkg-config cmake yasm nasm meson ninja-build gettext autopoint \
    openjdk-17-jdk-headless
```

- JDK 17（AGP 8.13 要求）
- Android SDK：`build-tools;36.0.0`、`platforms;android-36`
- Android NDK：`21.4.7075529`（32 位 arm）
- 预编译 contrib 包（约 140 MB）
- `extras/tools` 里的 `protoc` 需要 **≥ 3.4.0**（contrib 的 protobuf 是 3.4.0，否则 chromecast 编译报 `generated by an older version of protoc`）

### 3.2 一键构建

```bash
# 1) core 源码放好并挂接
ln -sfn /path/to/vlc_core-3.6.5 libvlcjni/vlc

# 2) 全流程（自检 → 初始化 → 编 native → 打包 AAR）
./build_libvlc_3.6.5_aar.sh

# 或分阶段
./build_libvlc_3.6.5_aar.sh check      # 环境自检
./build_libvlc_3.6.5_aar.sh init       # 建软链、local.properties、gradlew
./build_libvlc_3.6.5_aar.sh native     # 只编 so（最耗时）
./build_libvlc_3.6.5_aar.sh aar        # 只打包 AAR
```

日志同时打印到终端并落盘到 `out/logs/build_<时间戳>.log`；
产物在 `out/`（`*.so` 与 `libvlc-release-<时间戳>.aar`）。

### 3.3 手工构建（等价命令）

```bash
./buildsystem/compile.sh -a arm -l -t -b release
GRADLE_ABI=ARMv7 ./gradlew -p libvlcjni publishToMavenLocal
```

## 四、注意事项

1. **`libvlcjni/vlc` 软链不要提交**（已在 `.gitignore` 排除），它指向 core 源码树。
2. **`compile.sh` 不会把 `RELEASE` 传给 `compile-libvlc.sh`**，只要 `build-android-*/config.h`
   存在就会跳过 configure —— 改了 configure 参数后必须删掉 `config.h` 才会生效。
3. **gradle 发行包走腾讯镜像**（`gradle-wrapper.properties` 已改），`services.gradle.org`
   在部分网络下只有 ~25 KB/s。
4. 源码目录不要在 `core.autocrlf=true` 的 Windows 侧做 `git checkout`，会把 LF 写成 CRLF，
   破坏 `#define` 续行与 shell 脚本。
5. 只编 32 位时用 NDK r21（`21.4.7075529`）；`arm64` 需要更新的 NDK。
